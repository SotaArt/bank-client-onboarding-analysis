# Анализ процесса подключения клиента к банковскому продукту

Учебно-практический проект по системному и бизнес-анализу: разбор текущего процесса подключения клиента (**As-Is**), выявление узких мест и проектирование оптимизированного процесса (**To-Be**) с описанием требований, API и работы с данными.

**Цель** — сократить срок подключения клиента с 2 рабочих дней до 30 минут, снизить долю ручных операций и повысить прозрачность процесса.

## Проблема (As-Is)

Процесс последовательный: заявка передаётся между менеджером и бэк-офисом, данные вводятся вручную, статус обновляется вручную.

```mermaid
flowchart TD
    A([Клиент подаёт заявку]) --> B[Менеджер принимает заявку]
    B --> C[Ручной ввод данных в CRM]
    C --> D[Передача заявки в бэк-офис]
    D --> E[Ручная проверка документов]
    E --> F{Документы корректны?}
    F -- Нет --> G[Запрос недостающих данных у клиента]
    G --> C
    F -- Да --> H[Запрос в скоринговую систему]
    H --> I{Одобрено?}
    I -- Нет --> J[Отказ]
    J --> K[Уведомление клиента]
    I -- Да --> L[Ручное одобрение]
    L --> K
    K --> M([Клиент получает результат])
```

## Решение (To-Be)

Автопроверка данных, единый статус заявки, автоматическое уведомление клиента; ручные операции — только для исключений.

```mermaid
flowchart TD
    A([Клиент подаёт заявку]) --> B[Заявка создаётся в CRM]
    B --> C[API-шлюз: передача данных]
    C --> D[Автопроверка паспортных данных]
    D --> E{Данные валидны?}
    E -- Нет --> F[Уведомление менеджеру о ручной проверке]
    F --> G[Менеджер уточняет данные]
    G --> B
    E -- Да --> H[Автоматический запрос в скоринг]
    H --> I{Одобрено?}
    I -- Нет --> J[Автостатус: отказ]
    I -- Да --> K[Автостатус: одобрено]
    J --> L[Автоуведомление клиента]
    K --> L
    L --> M([Клиент получает результат])
```
